# EnjoyAgent Frontend Plan

## 文件用途

这份文档用于约束前端的推进顺序，避免一开始就把页面铺得过散。当前前端应该遵循一个原则：

`先把主链做通，再补运营页，再做精细体验。`

后端现在已经有比较完整的业务闭环，所以前端最合理的做法不是“先把所有页面壳子搭完”，而是围绕真实后端主链，一阶段一阶段把可用页面做出来。

## 前端目标

前端最终建议拆成两条主视角：

- 用户工作台
  - 创建和使用 Agent
  - 管理知识库、MCP、模型、钱包、市场安装
- 管理后台
  - 管理官方模型
  - 审核充值单
  - 审核市场资产
  - 查看计费和平台运营数据

第一版前端不建议一开始就把这两套视角做成两个独立工程，优先用一个前端项目，通过路由分区来承载：

- `/app/**`
- `/admin/**`

## 推荐技术栈

我建议前端采用下面这套栈，原因是它比较适合你现在这个项目的节奏：既要能快速承接后台能力，又要给后面做聊天体验、市场页和管理后台留出定制空间。

### 核心框架

- Vue 3
- TypeScript
- Vite

原因：

- 你这个项目原本就更适合 Vue 生态，学习成本和国内资料都更友好
- Vite 启动快，适合频繁联调
- TypeScript 对复杂表单、状态和 API DTO 很有帮助

### 路由与状态

- Vue Router
- Pinia

建议分工：

- Pinia 只放真正的客户端状态
  - 当前用户
  - 当前租户信息
  - 当前聊天面板本地状态
  - 主题和布局状态
- 服务端数据不要全塞 Pinia

### 服务端数据管理

- `@tanstack/vue-query`

原因：

- 你的前端会有大量查询型页面
  - Agent 列表
  - 知识库列表
  - 钱包流水
  - 市场资产列表
  - 管理端审核列表
- 这些数据更适合交给 Query 做缓存、失效、重试和分页状态管理

### 网络请求

- `axios`
- SSE 使用 `@microsoft/fetch-event-source` 或原生 `fetch + ReadableStream`

原因：

- 普通 CRUD 用 `axios` 足够稳定
- 聊天流式输出不能只靠普通请求，最好提前把 SSE 链路选型定下来

### UI 与样式

- Tailwind CSS
- `shadcn-vue`
- Radix Vue
- CSS Variables
- TanStack Table
- Lucide Icons

现在已经明确的 UI 方向是：

- 视觉风格参考 Dify
- 用 `shadcn-vue + Tailwind` 做主设计系统
- 不走传统重型后台模板风

不建议一开始直接重度依赖整套后台组件库，例如把所有页面都做成很强的 Element/Naive Admin 风格。原因是：

- 你后面会有聊天页、市场页、安装流程页，这些页面更适合定制化布局
- 太重的 UI 框架会让用户工作台和聊天体验变得很模板化

更好的策略是：

- 表格、弹窗、表单交互可以参考后台组件模式
- 整体视觉和布局保留自由度

更细的设计约束和布局方案见：

- [UI-STYLE.md](./UI-STYLE.md)

### 表单与校验

- `vee-validate`
- `zod`

适用场景：

- 登录注册
- Agent 创建/更新
- 模型配置
- MCP OAuth 配置
- 管理端审核表单

### 工具库

- `@vueuse/core`
- `dayjs`
- `clsx`

### 图表

- `echarts`

说明：

- 不用第一阶段就接
- 留给管理后台的统计页再接最合适

### 测试

- Vitest
- Vue Testing Library
- Playwright

建议顺序：

- 先补组件和页面级单测
- 关键主链再补 E2E

### 包管理与规范

- `pnpm`
- ESLint
- Prettier

## 建议目录结构

建议前端最终按这个结构演进：

```text
EnjoyAgent-frontend/
  src/
    app/
      router/
      layouts/
      pages/
      stores/
      components/
      modules/
      services/
      composables/
      styles/
      utils/
      types/
```

其中 `modules/` 建议按业务域拆：

- `auth`
- `agent`
- `chat`
- `knowledge`
- `mcp`
- `billing`
- `market`
- `admin`

## 分阶段开发计划

下面这套顺序，是按“越靠前越应该先做”的方式排的。

### 阶段 0：前端基础工程

目标：

- 初始化 Vue 3 + TypeScript + Vite
- 接入 Vue Router、Pinia、Vue Query
- 接入 Tailwind CSS
- 建好基础目录结构
- 建立 `api client`、错误处理、鉴权拦截器
- 建立最基础的全局布局和路由守卫

这一阶段适合完成：

- 登录页占位
- 404 页
- 基础侧边栏和顶部导航
- `app` 与 `admin` 两套路由壳子

完成标准：

- 前端项目能独立启动
- 可以连到后端接口
- 登录态能保存和失效

暂时不要做：

- 大量业务页面
- 复杂主题系统
- 视觉精修

### 阶段 1：认证与应用骨架

目标：

- 登录
- 注册
- 当前用户信息获取
- 路由鉴权
- 基础工作台布局

这一阶段适合完成：

- 登录页
- 注册页
- 工作台首页
- 用户下拉菜单
- 左侧导航结构
- 管理端入口路由判断

完成标准：

- 用户可以注册、登录、退出
- 普通用户和管理员路由边界清晰

### 阶段 2：模型、凭证、Agent 基础管理

目标：

- 先把 Agent 工作台最基础的 CRUD 管起来

这一阶段适合完成：

- 凭证管理页
- 用户模型配置页
- 官方模型列表页
- Agent 列表页
- Agent 创建/编辑抽屉或表单页

完成标准：

- 用户能完成“创建凭证 -> 创建模型 -> 创建 Agent”
- 官方模型可以被选中绑定到 Agent

暂时不要做：

- 聊天主工作台的复杂交互
- 市场安装向导

### 阶段 3：聊天工作台

这是第一批真正体现产品体验的页面。

目标：

- 让用户可以在前端里真正使用 Agent 聊天

这一阶段适合完成：

- 会话列表
- 聊天主面板
- 消息渲染
- SSE 流式输出
- 新建会话
- 检索调试信息面板
- 模型来源、token、调用来源等辅助信息展示

完成标准：

- 普通聊天能稳定使用
- RAG 聊天能看到引用和检索调试信息

这一阶段建议重点做体验，不要只做表格页。

### 阶段 4：知识库模块

目标：

- 让用户能在前端上完整管理知识库和文档

这一阶段适合完成：

- 知识库列表页
- 知识库详情页
- 文档上传
- 文档状态展示
- Chunk/检索调试辅助信息
- 知识库与 Agent 的绑定入口

完成标准：

- 用户可以上传文档并看到处理状态
- 用户能确认知识库是否处于可检索状态

### 阶段 5：MCP 模块

目标：

- 让用户能在前端完成 MCP 配置、工具管理和授权

这一阶段适合完成：

- MCP Server 列表页
- MCP Server 创建/编辑页
- Tool 目录展示页
- Agent Tool 绑定页
- OAuth 授权状态页
- 连接状态和错误提示

完成标准：

- 用户能配置 MCP
- 能看清有哪些 Tool
- 能把 Tool 绑定到 Agent

### 阶段 6：钱包、充值与官方模型体验

目标：

- 把平台计费体系在用户端真正落地出来

这一阶段适合完成：

- 钱包余额页
- 充值单列表页
- 创建充值单弹窗
- 钱包流水页
- 官方模型说明页
- 官方模型用量或扣费记录展示

完成标准：

- 用户能看见自己的余额、流水、充值状态
- 用户能明确区分“自己的模型”和“平台官方模型”

### 阶段 7：共享市场

目标：

- 把市场从后台能力变成真正可操作的前端产品

这一阶段适合完成：

- 市场首页
- 市场列表
- 资产详情页
- 提交资产页
- 安装确认页
- 安装结果页

适合先做的资产顺序：

1. Agent
2. Knowledge Base
3. MCP Server

完成标准：

- 用户可以浏览市场
- 用户可以提交和安装市场资产
- 用户能看见安装结果和关联资源

### 阶段 8：管理后台

目标：

- 让管理员真正具备平台运营能力

这一阶段适合完成：

- 官方模型管理页
- 官方模型凭证管理页
- 充值单审核页
- 市场审核页
- 市场上下架管理页
- 计费事件与钱包查询页

完成标准：

- 管理员不需要直接查数据库也能做主要运营动作

### 阶段 9：体验优化与工程化

目标：

- 把“能用”提升到“稳定、清晰、可扩展”

这一阶段适合完成：

- 页面骨架屏
- 统一错误态和空状态
- 表格分页与筛选体验优化
- 响应式适配
- 组件沉淀
- 单元测试和 E2E
- 埋点和简单审计前端视角

完成标准：

- 前端主链交互稳定
- 页面之间风格一致
- 核心路径具备基础测试

## 当前最推荐的前端开发顺序

如果你现在准备正式开始写前端，我建议按这个顺序推进：

1. 阶段 0：前端基础工程
2. 阶段 1：认证与应用骨架
3. 阶段 2：模型、凭证、Agent 基础管理
4. 阶段 3：聊天工作台
5. 阶段 4：知识库模块
6. 阶段 5：MCP 模块
7. 阶段 6：钱包、充值与官方模型体验
8. 阶段 7：共享市场
9. 阶段 8：管理后台
10. 阶段 9：体验优化与工程化

## 我对前端技术栈的最终建议

如果只给一版最推荐方案，我建议就是：

- Vue 3
- TypeScript
- Vite
- Vue Router
- Pinia
- TanStack Vue Query
- Axios
- Tailwind CSS
- vee-validate + zod
- VueUse
- Playwright

这套栈的优点是：

- 足够现代
- 对聊天、表单、管理后台都适配
- 可定制空间大
- 不会把 UI 早早锁死在某个很重的后台模板里

## 后续协作方式

这份计划先解决“做什么、先做什么”的问题。

等你下一步提出 UI 和布局要求时，可以继续在这个基础上细化：

- 信息架构
- 页面布局
- 视觉方向
- 组件设计
- 哪一阶段先落哪些页面
